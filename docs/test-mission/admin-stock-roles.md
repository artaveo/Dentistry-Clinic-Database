## نقش‌ها/قفل (API)
* ۵ رمز غلط → حساب قفل؛ پیام «account_locked» (برای نام کاربری ناموجود «اشتباه») یعنی وجود نام کاربری لو می‌رود (جزئی). مالک می‌تواند باز کند (users.unlock درست).
* قفل صفحه: وقتی lock است همه‌ی درخواست‌ها session_locked؛ رمز غلط رد؛ logout توکن را باطل می‌کند. کاربر غیرفعال نمی‌تواند وارد شود. مالک خودش را غیرفعال/تنزل نمی‌دهد. admin نمی‌تواند کاربر owner بسازد.
* UI ورود: پیام «نام کاربری یا رمز عبور اشتباه است» خوب.
* زبان en تمیز (بدون متن فارسی، ltr)، ps rtl؛ در ps کلمات لاتین فقط در داده‌ی seed (کدها).
* هنوز تست‌نشده: قفل بیکاری در UI، تم تیره/روشن، تقویم میلادی، ۱۴۴۰×۹۰۰، ۱۳۶۶ همه‌ی صفحه‌ها (فقط ۱۲۸۰ بررسی افقی)، LAN pairing (فقط status)، لایسنس (فقط status: unactivated)، نقش حسابدار/منشی/دستیار در UI.

* انبار UI: دریافت (مقدار abc/-5/0 رد با پیام «مقدار درست نیست؛ عددی بزرگ‌تر از صفر بنویسید»؛ 1.5 درست ثبت شد = ۱٫۵ بسته)، مصرف بیش از موجودی رد («به این اندازه موجودی قابل مصرف نیست»)، مصرف ۱ ثبت شد، جزئیات + لات + تاریخچه، غیرفعال‌کردن جنس («از فهرست‌ها پنهان است. سابقه‌ی آن حفظ می‌شود»)، تأیید حذف.

## اسکیل‌ها — واقعاً فراخوانی شد
* `nielsen-usability-heuristics`: H2/H4: واژه‌ی انبار/گدام، داکتر/دکتر، کدهای خام audit (R-16، R-19)؛ H3: بدون Undo مصرف (R-24)؛ H5: بدون هشدار انقضا هنگام دریافت (R-03)، غیرفعال‌سازی بدون تأیید؛ H9: پیام‌ها خوب و دقیق («عددی بزرگ‌تر از صفر بنویسید») ولی «این کادر لازم است» غیرمعمول (R-07)؛ H10: متن زنگ اعلان «فازهای بعدی» (R-17)؛ H8: صفحه‌ی انبار ۴ کارت + نوار فیلتر قبل از جدول (R-08)؛ H1: toast ثبت می‌شود (✓).
* `accessibility-audit`: فقط بررسی درون‌خطی (DOM + کیبورد) روی ورود، انبار، تنظیمات، کاربران؛ axe-core و AT نصب/اجرا نشد → conformance «نامعلوم»؛ ◐ تضاد رنگ متن ثانویه‌ی خاکستری روی پس‌زمینه‌ی روشن اندازه‌گیری نشد.
* `impeccable` (critique): فقط نقد بصری روی عکس‌ها؛ context script اجرا نشد (برنامه‌ی Operate): سلسله‌مراتب خوب (RTL درست، آیکون+برچسب سایدبار)؛ ضعف: ردیف‌های انبار با آیکون‌های مبهم، کارت‌های KPI بزرگ برای عدد ۰ (فضای اضافه)، منوی فرعی تنظیمات + جدول خدمات در ۱۲۸۰ تنگ.
* `ux-audit`: فراخوانی شد ولی **کامل اجرا نشد** (بدون Interaction Manifest کامل، بدون axe، بدون perf-metrics، بدون هر ۱۱ سناریو) → حکم صادقانه: **Incomplete**.

## UI نقش‌ها (roles.mjs، واقعی)
* **منشی:** منو = داشبورد، بیماران، نوبت‌ها، مالی، **انبار**، تنظیمات(فقط «درباره»). بدون گزارش/کاربران (درست). ولی انبار با تب خریدها و تأمین‌کنندگان باز است (R-21 در UI تأیید شد).
* **حسابدار:** داشبورد، بیماران، مالی، انبار، گزارش‌ها، تنظیمات(درباره). نوبت‌ها پنهان (درست)؛ فهرست بیماران با شماره تلفن را می‌بیند؛ «خروجی Excel» دارد.
* **مدیر (administrator):** همه‌ی منوها + تنظیمات کامل (کاربران، پشتیبان) — و طبق R-11 می‌تواند رمز مالک را عوض کند؛ UI کاربران هم همین را اجازه می‌دهد (نیاز به تست مستقیم UI؛ API تأیید شد).
* دستیار (assistant) در UI تست نشد (حسابش را برای تست غیرفعال کرده بودم).
