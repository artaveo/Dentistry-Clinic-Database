# بخش ۱۱ — چک‌لیست ۳۰ دقیقه‌ای «قبل از نشان دادن به مشتری» و سناریوی ارائه

شناسه‌ها: `MT-FIN-*`

## الف) آماده‌سازی کامپیوتر ارائه (یک ساعت قبل)

| # | کار | نتیجه |
|---|---|---|
| ۱ | یک **کلینیک نمونه برای ارائه** (نه داده واقعی، نه کلینیک تست شما) با نام قشنگ بسازید یا از پشتیبان تست بازیابی کنید؛ بیماران ساختگی با نام‌های دری/پشتو/انگلیسی | ☐ |
| ۲ | مجوز **فعال** است (نه «لایسنس وارد نشده»)؛ `تنظیمات ← مجوز` را ببینید | ☐ |
| ۳ | قیمت خدمات پرکاربرد وارد شده (نه «بدون قیمت») | ☐ |
| ۴ | حداقل ۱ داکتر، ۲ یونیت، چند نوبت **برای امروز و ساعت‌های بعد** (نوبت گذشته ثبت نمی‌شود) | ☐ |
| ۵ | زبان فارسی، تقویم شمسی، تم روشن (برای پروژکتور بهتر است)؛ «حالت کارایی» اگر لپ‌تاپ ضعیف است | ☐ |
| ۶ | پشتیبان تازه روی فلش؛ فلش مورد اعتماد شده | ☐ |
| ۷ | پرینتر وصل و تست؛ یا «بدون پرینتر — فقط PDF» | ☐ |
| ۸ | رزولوشن ۱۳۶۶×۷۶۸ یا پروژکتور؛ مقیاس ویندوز ۱۰۰٪؛ اعلان‌های ویندوز خاموش (Focus) | ☐ |
| ۹ | اینترنت **را قطع** کنید تا نشان دهید «بدون اینترنت کار می‌کند» | ☐ |
| ۱۰ | Recovery Key همین کلینیک کنار شماست (برای صحبت «امنیت») | ☐ |

## ب) چک‌لیست دودی ۳۰ دقیقه‌ای (`MT-FIN-01..20`)

هر ردیف باید در **کمتر از ۲ دقیقه** تمام شود. اگر یکی **رد** شد، ارائه را نگه دارید.

| شناسه | کار | باید ببینید | زمان | نتیجه |
|---|---|---|---|---|
| FIN-01 | برنامه را باز کنید | تا صفحه ورود < ۵ ثانیه؛ نام/لوگوی کلینیک | ۱ | ☐ ☐ |
| FIN-02 | ورود مالک؛ «درباره برنامه» | نسخه 0.12.3؛ سلامت دیتابیس «سالم»؛ «نسخه نهایی» | ۱ | ☐ ☐ |
| FIN-03 | `مجوز` | «مجوز فعال» | ۱ | ☐ ☐ |
| FIN-04 | بیمار جدید با نام فارسی/پشتو + تلفن | ذخیره؛ شمارهٔ بیمار | ۲ | ☐ ☐ |
| FIN-05 | جستجو با تلفن بدون صفر | پیدا می‌شود | ۱ | ☐ ☐ |
| FIN-06 | نوبت امروز + «بیمار رسید» + صف | صف با شماره | ۲ | ☐ ☐ |
| FIN-07 | سوابق پزشکی: دیابت + حساسیت | بنر هشدار بالا | ۲ | ☐ ☐ |
| FIN-08 | چارت: پوسیدگی ۳۶ ← پلان ← درمان | «تمام‌شده» | ۳ | ☐ ☐ |
| FIN-09 | فاکتور با تخفیف + پرداخت جزئی | مانده درست (حساب با ماشین‌حساب) | ۲ | ☐ ☐ |
| FIN-10 | چاپ رسید (یا PDF) | فارسی خوانا، سربرگ | ۲ | ☐ ☐ |
| FIN-11 | قسط‌بندی فاکتور ۳ قسط | مجموع = مانده | ۲ | ☐ ☐ |
| FIN-12 | نسخه با هشدار حساسیت | هشدار + چاپ | ۲ | ☐ ☐ |
| FIN-13 | بستن صندوق | مورد انتظار = نقد − بازپرداخت − هزینه | ۲ | ☐ ☐ |
| FIN-14 | گزارش «درآمد روزانه» + Excel | عدد برابر صندوق | ۲ | ☐ ☐ |
| FIN-15 | داشبورد | عددها با گزارش جور | ۱ | ☐ ☐ |
| FIN-16 | منشی وارد شود | بدون گزارش/تنظیمات | ۲ | ☐ ☐ |
| FIN-17 | پشتیبان دستی + فلش | «بررسی‌شده»؛ روی فلش | ۲ | ☐ ☐ |
| FIN-18 | قفل صفحه و بازکردن | اطلاعات پشت قفل پنهان | ۱ | ☐ ☐ |
| FIN-19 | تم تیره/روشن + زبان انگلیسی و برگشت | درست | ۱ | ☐ ☐ |
| FIN-20 | بستن برنامه با Task Manager و باز کردن | سالم؛ پیش‌نویس | ۱ | ☐ ☐ |

جمع ≈ ۳۰ دقیقه. اگر عدد مالی یا ذخیره‌شدن داده رد شد = **بحرانی**.

## ج) سناریوی ارائه به داکتر (≈ ۲۵ دقیقه)

**اصل:** داستان بگویید («یک روز کاری شما»)، نه فهرست امکانات. هر بخش ۲–۳ دقیقه. با «چرا برای شما مهم است» شروع کنید.

| زمان | چه نشان بدهید | چه بگویید | مراقب باشید |
|---|---|---|---|
| ۰–۲ | صفحهٔ ورود و داشبورد | «برنامه بدون اینترنت کار می‌کند. اطلاعات بیماران فقط روی کامپیوتر شما و رمزنگاری‌شده است؛ به سرور ما نمی‌رود.» | اینترنت را قطع کرده باشید |
| ۲–۵ | بیمار جدید، جستجوی ساده (نام/تلفن/شماره)، تشخیص بیمار تکراری | «هر بیمار با نام دری یا پشتو یا انگلیسی؛ تلفن را هر جور بنویسید پیدا می‌کند.» | نام‌های ساختگی |
| ۵–۷ | نوبت: تقویم، رنگ هر داکتر، جلوگیری از تداخل، «بیمار رسید» و صف | «منشی بیمار را می‌رساند، داکتر در صف می‌بیند.» | نوبت برای ساعت آینده |
| ۷–۱۱ | سوابق پزشکی + **بنر هشدار** (دیابت، حساسیت پنی‌سیلین، حاملگی)؛ **چارت دندان**: ثبت پوسیدگی، پلان درمان، قیمت از تعرفه، ثبت جلسه عصب‌کشی | «هشدار همیشه بالای پرونده است؛ هنگام نسخه هم هشدار می‌دهد.» | چارت را با «مراحل» ساده نشان بدهید؛ پریو را رد کنید (می‌توانید خاموش کنید) |
| ۱۱–۱۴ | نسخه: قالب آماده، هشدار حساسیت، چاپ A5 با نام و جواز شما؛ رضایت‌نامه | «داروها به لاتین، دستور مصرف به زبان بیمار.» | فهرست داروها را خود داکتر ببیند و اصلاح کند |
| ۱۴–۱۹ | **مالی**: فاکتور از درمان‌ها، تخفیف، پرداخت جزئی، رسید شماره‌دار، **قسط‌بندی ارتودنسی**، فهرست بدهکاران و اقساط، بستن صندوق | «هیچ پولی گم نمی‌شود؛ فاکتور بعد از صدور تغییر نمی‌کند؛ فقط ابطال یا یادداشت اعتبار با دلیل.» | عددها را از قبل بدانید؛ ارتودنسی را «بعد از اولین جلسه، کل مبلغ یک‌بار + اقساط» توضیح بدهید |
| ۱۹–۲۱ | گزارش‌ها: درآمد روزانه، سود و زیان، بدهکاران، درآمد هر داکتر؛ Excel | «در آخر ماه ببینید چقدر درآمد/هزینه و کدام بیمار بدهکار است.» | فقط ۴ گزارش نشان دهید |
| ۲۱–۲۳ | پشتیبان: خودکار شبانه، فلش، ابر؛ **Recovery Key**؛ «اگر لپ‌تاپ سوخت» | «همه چیز با فلش و آن کاغذ برمی‌گردد.» | کلید را نشان ندهید؛ فقط «کاغذ» |
| ۲۳–۲۵ | نقش‌ها (منشی، داکتر، حسابدار)، قفل صفحه، چند کامپیوتر (توضیح، نه نمایش مگر آزموده باشید) | «هر کس فقط کار خودش را می‌بیند.» | LAN را زنده نشان ندهید مگر چند بار آزموده باشید |

### نقاط قوت برای برجسته کردن
۱) دری/پشتو/انگلیسی با راست‌به‌چپ واقعی و تقویم شمسی ۲) بدون اینترنت ۳) امنیت (رمزنگاری + Recovery Key) ۴) چارت دندان تصویری با رنگ وضعیت‌ها ۵) ارتودنسی چندجلسه‌ای + اقساط ۶) هشدار پزشکی و نسخه ۷) پشتیبان‌گیری چندلایه ۸) ثبت همه‌چیز (Audit) ۹) آسان برای تک‌داکتر (ساده‌شدن فرم‌ها).

### چیزهایی که **باید بدانید و صادقانه بگویید** (یا ننمایید)
| موضوع | صادقانه چه بگویید |
|---|---|
| قیمت‌ها | «قیمت خدمات را خود کلینیک می‌گذارد؛ در نصب اول خالی است. ما کمک می‌کنیم.» |
| پیامک / واتساپ | «یادآوری نوبت فعلاً لیست تماس است؛ پیامک خودکار در این نسخه نیست.» |
| چند شعبه | «هر کلینیک یک نصب؛ گزارش مرکزی چند شعبه فعلاً نیست.» |
| چندکامپیوتری | «هست و آزمایش شده؛ هنوز در کلینیک واقعی تجربه نشده» (اگر LAN را نیازموده‌اید) |
| چاپ حرارتی | «از طریق ویندوز چاپ می‌شود؛ مدل پرینتر را با هم امتحان می‌کنیم» |
| متن پشتو | «ترجمه پشتو در حال بازبینی با گوینده بومی است» |
| SmartScreen | «برنامه گواهی امضا ندارد؛ ویندوز یک‌بار هشدار می‌دهد؛ امن است» |
| مجوز | «نصب با مجوز فعال می‌شود؛ بدون آن فقط دیدن و پشتیبان‌گیری ممکن است؛ اطلاعات هرگز گروگان نیست» |
| آپدیت | «آپدیت امضاشده و با پشتیبان؛ ممکن است در ابتدا دستی باشد» |

### نمایش ندهید
حالت پریو (اگر داده ندارید)، لابراتوار + فرمایش چاپی (به هم وصل نیست)، قیمت صفر، ورود Excel بیماران (نگاشت ستون ممکن است سؤال بپرسد)، «آپدیت خودکار»، LAN زنده (مگر آزموده)، ساعت ویندوز، «حالت امن».

## د) بعد از ارائه
پشتیبان بگیرید؛ پرسش‌های داکتر را بنویسید (آیا «مالی را داکتر ببیند؟»، «نسخه چه فیلدی کم دارد؟»)؛ فهرست [تصمیم‌های باز](13-known-issues.md) را با او مرور کنید.
