# ADR-04 — نگهداری کلید رمز (به‌روزرسانی فاز ۰)

**وضعیت:** پذیرفته‌شده · **شواهد:** [Spike 1](../spikes/01-tauri-sqlcipher-dpapi.md)

## تصمیم
* دو نسخه از کلید داده کنار دیتابیس:
  * `clinic.key` — کلید Wrap‌شده با **DPAPI، `CRYPTPROTECT_LOCAL_MACHINE`** + Entropy مخصوص برنامه. فقط روی همین کامپیوتر باز می‌شود.
  * `clinic.rkey` — کلید Wrap‌شده با **Recovery Key** (HKDF-SHA256 → XChaCha20-Poly1305). همراه **هر Backup** کپی می‌شود.
* Recovery Key: ۱۶۰ بیت تصادفی + ۱۶ بیت Checksum، Base32، ۶ گروه ۶ حرفی (`XXXXXX-XXXXXX-…`). ورودی نسبت به حروف کوچک/فاصله/خط تیره و اشتباه‌های رایج (0/O، 1/I، 8/B) مقاوم است و غلط تایپی قبل از Restore تشخیص داده می‌شود.
* Restore روی کامپیوتر جدید: Recovery Key ← باز کردن کلید ← بررسی Integrity ← محافظت مجدد با DPAPI همان کامپیوتر.
* Machine Scope (نه User Scope) چون سرور LAN به‌صورت Service اجرا می‌شود و کارمندان حساب ویندوز مشترک ندارند.

## پیامدها
* DPAPI در برابر **سرقت کل دیسک** با ابزار تخصصی مقاوم نیست ← Setup Wizard وضعیت BitLocker را بررسی و در صورت غیرفعال بودن هشدار می‌دهد (ریسک R-09).
* بدون Recovery Key و بدون کامپیوتر اصلی، داده قابل بازیابی نیست (عمداً) ← چاپ اجباری در Setup (ریسک موجود در Roadmap).
